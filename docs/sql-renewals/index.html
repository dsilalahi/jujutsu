Estimation notes

  • Azure Hybrid Benefit + reservations can reduce cost substantially versus pay-as-you-go (Microsoft cites up to ~85% in some scenarios when combined with other savings).
  • PaaS options (Database, Managed Instance) usually lower operational cost; VM keeps more of the current admin model.
  • Use Azure Migrate or the Azure pricing calculator for numbers based on your actual CPU, memory, storage, and region.

These are directional. Confirm current rates and eligibility on Azure SQL pricing and Azure Hybrid Benefit.

    Suggested next steps

    1. Run Azure Migrate (or the SQL assessment in SSMS / Azure Arc) to inventory instances, feature use, and sizing.
    2. Group databases that must move together (shared jobs, cross-DB queries, linked servers).
    3. Confirm Software Assurance status and Hybrid Benefit eligibility.
    4. Pick a migration method for the target:
      • Managed Instance → Managed Instance link (near-zero downtime) or Azure DMS / log replay
      • Azure SQL Database → DMS offline, BACPAC, or data movement tools (more app changes possible)
      • SQL on VM → backup/restore, log shipping, or distributed availability groups
    5. Pilot one non-critical database, validate performance and features, then plan the cutover window.
    6. After migration, review reserved capacity and right-sizing once you have real usage data.
